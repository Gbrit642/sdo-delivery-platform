⚠️ The Core Problem: Managed Agent API Limitation

Google Cloud's Managed Agent API currently operates in a sandboxed runtime with strict egress and credential limitations:

  • No Dynamic 3rd-Party OAuth: Managed Agents cannot independently perform OAuth 2.0 user-delegated token exchanges to third-party SaaS MCPs (e.g. Databricks, Salesforce, NetSuite, Jira, ServiceNow).
  • Identity Boundary Bypass: Calling external databases directly from autonomous agents risks credential leakage or cross-tenant data exfiltration.

🚀 The Target Solution: Agent Gateway with Dual-Identity

Our platform resolves this by inserting the Agent Gateway as the centralized enterprise policy and credential mediation plane:

  • Dual-Identity Propagation: Intercepts Google Workspace OIDC JWT / IAP identity (sarah.controller@wallbox.com), cleanly separating human credentials from agent service accounts.
  • Governed MCP Client Connectors: Manages token exchange securely within the customer's enterprise boundary.

⚡ Path 1: Direct Connector Automation (Recommended)

Default behavior for 90%+ of business queries:

  • Speed: Executes in < 5 seconds.
  • Active Compute: $0 server compute (no idling containers or VM pods).
  • Deliverable: Creates a governed BigQuery Federated SQL View querying Databricks via BigQuery Omni or external connector.
  • Human Governance: Mandatory Gate H1 (Spec Sign-Off) and Gate H2 (Activation Sign-Off).

🧠 Path 2: Autonomous Multi-Agent Synthesis

Reserved strictly for complex bespoke software development:

  • Speed: 2–5 minutes.
  • Environment: Synthesizes custom Python modules, runs unit tests in ephemeral Linux sandboxes, and squash-merges GitHub PRs.
  • Human Governance: Mandatory Gate H1 and Gate H2 sign-offs.

5. Path 1 Selection & Gate H1 (Spec Sign-Off) Human Governance
Platform recommends Path 1: Direct Connector Automation (<5s, $0 server compute). DocumentalAgent synthesizes spec.md with Gherkin scenarios. Sarah reviews and approves Gate H1.
spec.md (Gherkin Contract) 
Feature: Cross-Platform Databricks + BigQuery Profitability View
  Scenario: Compute average revenue per kWh by customer
    Given BigQuery table "sdo_finance_demo.invoices" containing billing records
    And Databricks table "catalog_prod.finance.charging_usage_logs" containing session logs
    When the view aggregates total EUR revenue and total kWh by customer_id and month
    Then avg_revenue_per_kwh must equal total_revenue_eur / total_kwh_delivered
    And zero division must be handled safely via SAFE_DIVIDE
6. Query Synthesis & Ephemeral Linux Sandbox Test Implementer & Reviewer
Generates federated SQL view query joining BigQuery and Databricks. Validates syntax with sqlfluff and executes mock assertions in an ephemeral Linux sandbox (100% pass rate).
BigQuery Federated SQL View 
CREATE OR REPLACE VIEW `managed-agent-504409.sdo_finance_demo.v_monthly_customer_profitability` AS
SELECT 
  inv.customer_id,
  DATE_TRUNC(inv.billing_date, MONTH) AS billing_month,
  SUM(inv.amount_eur) AS total_revenue_eur,
  SUM(db.kwh_consumed) AS total_kwh_delivered,
  SAFE_DIVIDE(SUM(inv.amount_eur), SUM(db.kwh_consumed)) AS avg_revenue_per_kwh
FROM `managed-agent-504409.sdo_finance_demo.invoices` AS inv
LEFT JOIN EXTERNAL_QUERY("projects/managed-agent-504409/locations/us/connections/databricks-con",
  '''SELECT customer_id, kwh_consumed, timestamp FROM catalog_prod.finance.charging_usage_logs'''
) AS db ON inv.customer_id = db.customer_id
GROUP BY 1, 2;
7. Gate H2 Activation Sign-Off & Zero-Code Handover Automated Deployment
Sarah approves Gate H2. The platform automatically deploys the view into BigQuery and presents a Business Deliverable Card with a 1-click console link and live sample table preview.
8. Immutable WORM Audit Record Cloud Storage WORM
SHA-256 state trajectory and execution metadata sealed into immutable WORM Cloud Storage bucket (sdo-worm-audit-managed-agent-504409) for SOC 2 Type II compliance.

🔍 Why This Outperforms Legacy Approaches

  • No Token Leaks: The LLM generates query logic referencing table schemas, but never handles raw passwords, OAuth bearer tokens, or database secrets.
  • Zero Customer Shell Friction: Sarah never touches terminal CLI commands (gcloud, python3, curl). Everything is executed automatically in the active project upon Gate H2 sign-off.
  • Multi-Cloud Support: Connects Google Cloud datasets with Databricks, Salesforce, NetSuite, and Jira under a single governed plane.
